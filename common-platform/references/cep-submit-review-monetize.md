Adobe reviews each plugin submission to help developers prepare their work for broad release and to protect the experience of users who install those plugins.

This document outlines the checks performed during review. It is long, but following the checklist helps confirm that requirements are covered before publication and reduces the chance of fixes and resubmission.

## Plugin Description

Use "Adobe Photoshop" in a plugin name only when the name follows the pattern "\${Plugin Name} for Photoshop". See the [Adobe Branding Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide.pdf) for more detail. Examples: 
OK: "Rectanglator", or "Rectanglator for Adobe Photoshop"   
 Not OK: "PS Rectanglator", or "Rectanglator PS". A plugin named "Rectanglator PS" would be rejected because of the name. 
The plugin description must be relevant and understandable without extra context. 
Provide an English description, no matter which other languages are supported. 
Listing material, including the author name, email address, and website, must follow the [Adobe Branding Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide-062218.pdf).
A plugin website must include an email address or contact form that lets users reach the plugin developer easily.  (The submitted website will be checked to verify that this information exists.) 
Do not include links in the listing to websites that are still being built (i.e., "under construction", "coming soon", etc.).

## Icons, screenshots and videos

- Plugin icons must exclude Adobe product assets and icons. (Many submissions are rejected because Adobe product icons appear in them.)
- Plugin icons need to appear sharp and undistorted.
- Plugin icons should remain easy to see when the Creative Cloud desktop app uses dark mode.
- Listing screenshots must not show Adobe product assets or icons unless the Adobe Branding team has already granted permission (CCDeveloperMarketing@adobe.com or brand@adobe.com).
- Listing videos must relate to the plugin or publisher. They must not show Adobe assets or icons unless permission has been obtained from the Adobe Branding team (CCDeveloperMarketing@adobe.com or brand@adobe.com).

## Adobe Branding Guidelines

- Review and follow the [Adobe Branding Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide.pdf) (login required).
- Avoid publisher names, domain names, email addresses, and similar property names that can look like Adobe brand, product, or service names already in use. Eg: <adobexd@gmail.com>, <AdobePS@gmail.com> or XYZforAdobe.com
- Adobe assets and icons require explicit Adobe permission before they can appear in a plugin or in plugin marketing material. Getting that permission can lengthen the review, approval, and publication timeline.

## Inappropriate Content

- The plugin and its related marketing surfaces must avoid intense violence, blood, gore, sexual content, nudity, and strong language.

- The plugin must not support or carry out phishing, spamming, hacking, password trafficking, or spyware, and it must not include malware, trojans, or viruses.

## External Services

- When a plugin needs paid credentials, the submission to Adobe must include test credentials for login, license key, API Key, or any other access needed for a complete review.

- Adobe reviewers must be able to reach every plugin function, either openly or by using the credentials supplied to Adobe.

## Installation Instructions

- If use of a plugin with Adobe products requires extra setup steps, include those steps in the "Where to find it" section. For example: after getting the plugin from the Creative Cloud desktop application, a user may need to move or place files in a required location, and those instructions need to be stated clearly in the "Where to find it" section.

- Provide installation instructions for every supported point product.

- Write instructions clearly and precisely so end users can find the plugin in each supported point product.

## ZXP installation

- The ZXP must install successfully.

- Once installation is complete, the plugin should appear in the intended location described in the "Where to find it" section.

- If opening the ZIP produces an EXE and/or DMG, verify that the plugin file matches the supported platform(s) listed in the listing information (for example "Windows only.").

## Plugin functionality and UI (User Interface)

After the user installs the plugin, review confirms that the newly added plugin works smoothly and that customers can use it to improve productivity.

### Functionality

1. The plugin must install without error.

2. It should open successfully in the highest supported version of the point product.

3. It should open successfully in the lowest supported version of the point product.

4. Modal dialogs need a visible UI control for closing them (e.g., a cancel/close button).

5. A completely blank UI must never appear.

6. No screen should trap users without a navigation path out.

7. When an internet connection is required but unavailable, the plugin must tell the user.

8. Behavior must match the developer's description.

9. Every external link in the plugin must open a website when clicked.

### User Interface

1. Plugin UI elements must not overlap or truncate.

2. Plugin content must comply with [Adobe Branding Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide.pdf).

3. Nothing in the content should be clipped.

4. UI content must wrap or adjust as needed for the available UI width.

5. When content does not fit on screen, the plugin UI must scroll.

## Performance

- The plugin must not reduce the performance of Adobe products.

- The plugin must load within a reasonable amount of time.

- The plugin must not create abnormal resource usage (e.g., CPU, RAM, storage).

- The plugin must not trigger crashes, system errors, or major failures.

## License Distribution

- Share the license code with the review team when end users must enter it in the plugin to activate the plugin.

- FastSpring stores the license keys, and when an end user purchases the plugin from Adobe Marketplace, FastSpring distributes the license key to that user.

- Developers may add license-key details in the "Notes to approver" section.

## Top 3 Rejection Reasons

During review, plugins are checked with the goal of ensuring that installed plugins give users a good experience. Rejections can occur, especially for first-time plugin submissions. In those cases, the requested changes must be completed before the plugin is submitted again for review.

## Top 3 Rejection Reasons — _Non-compliance with Adobe Branding Guidelines._

Developers sometimes add Adobe brand assets before receiving permission, such as Adobe's "A" icon. That conflicts with the [Adobe Branding Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide.pdf). Request approval from the Adobe Branding Team at <brand@adobe.com> before using Adobe assets. After permission is granted, those Adobe assets may be used on the website and in screenshots.

## Top 3 Rejection Reasons — _Plugin does not function as described by the developer._

- During testing, the review team checks all plugin functionality. Before submitting, verify that the plugin works as advertised and that every feature functions properly.

- Silent failures: When a plugin user tries an unsupported function, the plugin must not fail silently. Show a dialog explaining that the action/functionality is unsupported so users understand the limitation and do not repeat the same action.

- The plugin must be compatible with every Adobe product, product version, and operating system listed in the "Product Compatibility Information" section of the listing.

## Top 3 Rejection Reasons — _Insufficient installation instructions._

- Installation instructions included with a submission are sometimes too vague for a user to find the plugin and install it for each supported Adobe application. Each supported version of an Adobe application should have its own instructions in the listing's "Where to find it" section.

- If the review team cannot find the files named in the "Where to find it" section of the listing, the plugin will be rejected. Provide the path users should follow inside the Adobe product to find this plugin.

## Adobe Branding Guidelines

Adobe periodically publishes a fixed body of branding rules for working with Adobe assets and product icons. Developers are expected to follow those rules closely.

Using Adobe assets with a product can help users recognize the Adobe relationship and trust that the plugin is intended to satisfy Adobe quality expectations.

Adobe does not permit product icons to be modified. Developers may include Adobe-published assets and logos in their products only when Adobe icons remain unchanged.

Review the [Adobe Branding Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide.pdf) carefully and apply them exactly. Submissions that miss these requirements can be rejected during review.

## Benefits & Best Practices — Best Practices

1.  **Use same developer AdobeID for both UXP and CEP plugins:** Submit both CEP and UXP plugins from the same developer ID. A shared ID makes plugin performance easier to follow, keeps listing management together, and simplifies responses to user comments.

1.  **Proper Description:** In the description field, explain the plugin's capabilities, features, functionality, and expected outcomes. End users benefit from a video that shows the plugin in action, because new users can understand how to work with it more quickly.

1.  **Update Your Plugin(s) Regularly:** Keep plugin(s) current so they remain compatible with the latest version of each supported point product. Regular updates improve the end-user experience and can affect revenue and ratings.

1.  **Share Test Credentials:** Provide test credentials to the review team through the "Notes to Approver" section. Including them with the listing submission helps the review move faster.

1.  **Share a License:** Some plugins require a license key before use. When your plugin works this way and FastSpring processes your payments, provide 100 license keys to the review team in the "Notes to Approver" section so the keys can be stored on FastSpring. FastSpring distributes a license key to users after they successfully purchase your plugin.

    - Note: Before the current license supply is depleted, asupport@adobe.com will ask you for additional licenses and will restore them on FastSpring so users can receive a key after purchase.

    - You decide how many licenses to keep on FastSpring. Adobe generally encourages sharing at least 100 licenses, but you may provide fewer or more license keys.

1.  **Provide Proper Installation Instructions:** Put clear installation directions in the "Where to find" section, including which files users install and where those files should be placed. If the plugin supports multiple Adobe products and the steps differ by product, provide separate instructions for each point product. (For example, include both sets of directions when Photoshop and InDesign require different installation steps.)

1.  **Follow the Adobe Brand Guidelines:** Before using any Adobe brand asset, such as product icons, read and comply with the [Adobe Brand Guidelines](https://partners.adobe.com/content/dam/tep_assets/public/public_1/documents/Adobe-Creative-Cloud-Developer-Brand-Guide.pdf). Do not use an asset in a listing or in marketing materials unless Adobe has granted the required authorization. Listings that use Adobe assets without prior approval can be rejected.

1.  **Provide Support:** Make sure users have a reliable way to contact you about plugin problems. Poor reviews and ratings often result when users cannot communicate with the developer.

1.  **Additional Payment:** If using the plugin requires any additional payment, disclose all related information to users and include it in the plugin description.

1.  **Companion application:** If the plugin needs any companion application to function, state that requirement in the plugin description and tell users where to download the companion application.

## FAQs — How can I generate coupon code(s)?

_Answer:_ Ask the Review Team to create one or more coupon codes for you. Send these details to the Review Team:

1. Extension name (or listing name)

2. Coupon validity period: Choose either a limited date range for the discount or a coupon that does not expire.

3. Percent off: State the discount percentage to offer to your user(s).

4. Coupon code and code format: Select one of the supported coupon formats, either a single coupon code or multiple random codes.

   - When using a single coupon code, choose a unique code for FastSpring to store. Whenever a user enters that coupon code on the payment page, the cart value receives the discount. (For example, "MYCOUPON-FREE".)

   - Multiple Random Codes: If you need, for example, 100 coupon codes, the Review Team generates them. Provide a five-character prefix to place at the start of every coupon code.

After coupon creation is finished, the Review Team will contact you. You can then give the coupon code(s) to customers and direct them to enter the code during checkout.

## FAQs — How can I submit a patch?

_Answer:_ Submit a patch when changing functionality for a listing that already exists. Functional updates can include bug fixes, new features, or both.

_Patch submissions allow edits to these fields:_

1. Upload File (Note: For a non-ZXP upload, the patch file type must match the parent upload file type.)

2. Version Number (Note: Only ZIP based extensions use this field. CEP based extensions get version numbers from the manifest file automatically, and those values cannot be typed in manually.)

3. EULA (End User License Agreements)

4. Where to Find It

5. Installation Instructions for Enterprise Users or Creative Cloud Teams users

6. Release Notes

7. Note to the approver

### How to submit a patch

1. Sign in to the [Exchange Developer Portal.](https://partners.adobe.com/exchangeprogram/creativecloud)

2. Open the Dashboard.

3. Choose your extension or listing by name; this step applies only after the listing has been published.

4. Use the "More" dropdown button in the upper-right corner and select "Create New Patch".

5. Then open the Patch Details Tab.

6. ZIP-based extensions allow the version number to be edited. ZXP-based extensions read version numbers automatically from the manifest file and do not allow manual changes.

7. To prevent immediate publication after approval, clear "Publish this patch immediately upon approval". With that option off, the approved patch is placed in the "Not Published" section of Dashboard, and you must publish it yourself before it appears in the Creative Cloud Exchange Marketplace.

8. Scroll down and click submit.

9. After submission, the Exchange Portal displays a success message for the requested changes, and confirmation email is sent from noreply@salesforce.com and ccintegrationsreview@adobe.com.

### How to submit a patch for a rejected submission:

1. When the previous patch submission was rejected, open the "Not Published" section and select the most recent rejected version.

2. Click the "Edit" button and choose the "Patch Details" tab.

3. Replace the file uploaded earlier with the new file.

4. Patch uploads must use the same file type as the parent file. For example, if the initial submission used a ZXP file, the patch submission must also upload a ZXP file.

If metadata or patch creation causes problems, contact the Review Team at ccintrev@adobe.com. Also review the [Exchange FAQs (Frequently Asked Questions).](https://partners.adobe.com/exchangeprogram/creativecloud/support/faq.html)

### Steps for submitting a Metadata Change Request:

1. Sign in to the [Exchange Developer Portal](https://partners.adobe.com/exchangeprogram/creativecloud) and open the [Dashboard.](https://partners.adobe.com/exchangeprogram/creativecloud/appslist.html)

2. In the "Published" tab, choose the listing that needs changes.

3. Select Edit.

4. Revise whichever tab needs changes: Details, Images, Upload & Docs, Notes & EULA.

5. Move down the page and click "Save & Next" (or back to switch between tabs).

6. After finishing the edits, click the "Save" button and preview the listing.

7. If the previewed changes are correct, click the "Submit" button.

8. A success message appears in the Exchange Portal after the changes are submitted. Submission email is sent from ccintegrationsreview@adobe.com and noreply@salesforce.com.

## FAQs — Can I reply to a review left by a user?

_Answer:_ Yes. You can respond to comments from the [Exchange Portal](https://exchange.adobe.com/apps/browse/cc) or through the Creative Cloud Desktop App.

## FAQs — How can I change the bundled ID for a CEP extension?

_Answer:_ The bundled ID uniquely identifies the extension. After publication, the bundled ID cannot be changed. To use a different bundled ID, create another listing.

## FAQs — How can I fix the following .`DS_S`tore or macOSX error?

- `DS_S`tore or \_MACOSX were detected and rejected in upload due to security reasons. Please upload a new package without these files. Please contact ccintrev@adobe.com with questions.

_Answer:_ A ZXP upload can show the .`DS_S`tore or macOSX error above because macOS places hidden files inside folders.

### How to Delete a `DS_S`tore File for a Specific Folder

**Note:** Without an administrator sign-in, Terminal may request your name and password before allowing the `DS_S`tore removal commands.

1. From the desktop, choose Go > Utilities > Terminal.

2. Find the folder that contains the `DS_S`tore file, then change to that directory in Terminal. For example, when the folder is on the desktop, run cd desktop and press Enter.

3. Type find . -name '.`DS_S`tore' -type f -delete and press Enter to remove every .`DS_S`tore file from the current directory.

4. Select OK. The chosen folder's .`DS_S`tore files will be deleted.

## FAQs — How can I add a collaborator, colleague, or teammate to the Exchange Portal?

_Answer:_ Give collaborators access when they need to update or revise your listing.

1. Sign in to the Exchange Developer Portal.

2. At the top right, click the "Edit Profile" button.

3. Click Add/Edit Users, then click "Invite contact".

4. Enter the contact's details (FirstName, LastName, Email) and click "Invite".

5. The requested user receives an invitation.

6. The collaborator must complete AdobeID registration from the email link.

7. After registration is complete, the collaborator needs to create an account on Exchange Developer Portal. Once that is done, the collaborator can update the listing.

## FAQs — How can I drop support for a Creative Cloud app while submitting a patch?

_Answer:_ Support for Creative Cloud apps cannot be removed during a patch submission (e.g., the listing supports Photoshop, Illustrator, and InDesign, and you now want to stop supporting Photoshop). The listing must continue to support every point product included in the first published version you submitted.

When developers can no longer support particular Creative Cloud apps, they need to submit a new listing and withdraw the old listing after the new one is approved.
