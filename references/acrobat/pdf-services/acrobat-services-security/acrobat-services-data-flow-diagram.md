For Adobe-managed assets, the caller authenticates, uploads input, submits a job and retrieves its result. The service produces and stores the output. The [data-flow diagram](https://raw.githubusercontent.com/AdobeDocs/pdfservices-api-documentation/main/src/pages/overview/images/data-flow.png) illustrates those boundaries; the sequence below identifies each participant's work.

1. The caller sends `client_id` and `client_secret` to `POST /token`, then retains the returned access token. Keep credentials in the trusted application environment. Follow the [token request](../step-1-getting-the-access-token.md).
2. The caller requests `POST /assets` with the input media type, Adobe bearer token and `x-api-key`. The response supplies `assetID` and a signed `uploadUri`.
3. The caller reads its input from local or external storage and sends the bytes with `PUT` to `uploadUri`. Finish this transfer before using the asset ID. The [asset upload procedure](../step-2-uploading-an-asset.md) covers both requests and their different headers.
4. The caller submits the operation-specific request with its input asset and options. Retain the job URL from the `location` response header. For example, [extraction submission](../step-3-creating-the-job.md) and [electronic-seal submission](../step-6-creating-the-job.md) use different body fields.
5. Adobe processes the job and stores its output. This is service work; the caller does not upload the generated result back to Adobe.
6. The caller polls the job URL and handles the operation's in-progress, completed or failed response. Read the completion contract for the chosen operation: extraction returns `content` and `resource` objects, while a seal result uses `asset`. A supported [callback notification](../webhook-notification.md) can notify the caller asynchronously.
7. The caller downloads the completed output from its returned signed URL and saves it in the intended persistent storage. Use the [extraction completion and download instructions](../step-4-fetching-the-status.md) or the selected operation's result contract; a submitted job or a temporary output URL is not a saved result.
8. After retrieving everything still needed, the caller can delete an Adobe-managed input or output asset with `DELETE /assets/{assetId}` and its Adobe authorization headers. A successful deletion returns `204`. The [asset deletion contract](https://developer.adobe.com/document-services/docs/apis/#operation/asset.delete) defines errors and authentication.

Adobe-managed assets have a default 24-hour lifetime. Preserve the returned identifiers and URLs: the API has no asset-listing operation. See [storage choices](adobe-acrobat-services-rest-api.md) for direct use of supported external storage, SDK-version differences and the Power Automate connector's deletion behavior. That external-storage request path differs from the Adobe-managed upload sequence above.
