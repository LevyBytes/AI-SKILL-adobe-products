PDF Services can read input and write output directly in supported external storage through signed URLs. A signed URL supplies temporary authorization to a specific resource; the application issuing it still needs the provider's permissions. The URL consumer can use that delegated access without receiving the issuer's separate storage credentials.

Choose the external-storage request variant for the operation in the [API reference](https://developer.adobe.com/document-services/docs/apis/). A shared external-input object uses `uri` for the download URL; an external-output object uses `uri` for the upload URL. The operation determines where those objects belong and whether external output is supported. Use the matching `storage` value: `S3`, `BLOB`, `DROPBOX` or `SHAREPOINT`. Operation-specific parameters and result handling still apply. The Adobe job request also requires its own [access token](step-1-getting-the-access-token.md).

Check [transport and redirect constraints](overview-external-storage-for-adobe-pdf-services-apis/overview-limitation.md), then select the [provider-specific access contract](overview-external-storage-for-adobe-pdf-services-apis/overview-supported-external-storage-solutions.md). Keep each URL valid for the period when the asynchronous job will use it. Use the [storage reference](overview-external-storage-for-adobe-pdf-services-apis/reference-index.md) for provider details and supported host patterns.
