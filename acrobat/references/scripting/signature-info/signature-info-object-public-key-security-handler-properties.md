# SignatureInfo object public key security handler properties

These extra properties are available for definition by public key security handlers:

| Property | Type | Access | Version (Key) | Description |
| --- | --- | --- | --- | --- |
| appearance | String | W | 5.0 | Names the user-set appearance applied while signing this field. Because PPKLite and PPKMS rely on the standard appearance handler here, you can look up the appearance names under the signature appearance configuration dialog box of the Security user preferences.<br><br>Leaving it unset falls back to the Standard Text appearance. Applies solely to visible signature fields. |
| certificates | Array | R | 5.0 | Holds an ordered chain of certificates identifying the signer. Position zero is the signer's own certificate; the entries that follow trace the chain upward to the certificate authority that issued it. Only a single entry appears here when the certificate is self-signed. |
| contactInfo | String | R/W | 5.0 | Stores whatever contact details the user supplied for trust decisions. A phone number that document recipients can dial to reach the author is one example. Relying on this to establish trust does not scale well and is discouraged. |
| byteRange | Array | R | 6.0 | Lists, as numbers, exactly which bytes this signature covers. |
| docValidity | Number | R | 6.0 | Reports the validity of the signature's document byte range digest as of the most recent signatureValidate call. Every PDF document signature field signature carries a byte range digest.<br><br>Return codes are explained under Validity Values. |
| idPrivValidity | Number | R | 6.0 | Reports how valid the signer's identity is. The meaning is handler-dependent; consult Private Validity Values for the values the Adobe.PPKLite and Adobe.PPKMS handlers produce.<br><br>Until the signature has been validated this stays 0 — that is, whenever status equals 1. |
| idValidity | Number | R | 6.0 | Gives the validity of the signer's identity expressed as a number.<br><br>For the return codes, consult the idValidity property entry in the table status and idValidity properties. |
| objValidity | Number | R | 6.0 | Reports the validity of the signature's object digest as of the most recent signatureValidate call. In PDF documents, object digests are carried by signature field certification signatures and by document-level application rights signatures. Object digests sign every FDF file.<br><br>Return codes are explained under Validity Values. |
| revInfo | Object | R | 7.0 | Wraps two properties, CRL and OCSP, inside one generic object. Each is an array of hex-encoded strings, and every string holds the raw bytes of the revocation data applied when revocation-checking a certificate.<br><br>CRL strings stand for CRLs; OCSP strings stand for OCSP responses. Because this data can grow very large, these arrays fill only when the relevant application preference is enabled. |
| trustFlags | Number | R | 6.0 | Each bit here marks something the signer is trusted to do. Treat the value as meaningful only while status equals 4. The recipient's trust database — the Acrobat Address Book (Adobe.AAB), for instance — is where these settings come from. Bit assignments are:<br><br>1: Trusted for signatures<br><br>2: Trusted for certifying documents<br><br>3: Trusted for dynamic content such as multimedia<br><br>4: Adobe internal use<br><br>5: The JavaScript in the PDF file is trusted to operate outside the normal PDF restrictions |
| password | String | W | 5.0 | Supplies the authentication password needed to reach a private key earmarked for signing. Whether it is demanded at all depends on what the security handler's policies require. |
